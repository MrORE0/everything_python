Anchor 1

Type hints: the syntax

name: str = "Hamburg"
temps: list[float] = [12.0, 8.9]
counts: dict[str, int] = {"Hamburg": 3}

def greet(name: str, times: int = 1) -> str:
    return (f"Hello, {name}! " * times).strip()
  • Hints are not enforced when the program runs
  • They are for humans, editors and tools like mypy
Anchor 2

mypy: static analysis

def double(x: int) -> int:
    return x * 2

double("21")
$ mypy demo.py
demo.py:4: error: Argument 1 to "double" has incompatible
  type "str"; expected "int"  [arg-type]
Static means checked without running the program. The bug is found before any user hits it.
Anchor 3

Handling None

def mean_temp(station: str) -> float | None:
    return STATIONS.get(station)

# mypy: could be None!
mean_temp("Oslo") + 1

# fix: handle None first
temp = mean_temp("Oslo")
if temp is not None:
    temp + 1
  • float | None means "a float, or nothing"
  • mypy forces you to handle the missing case
  • One of the most common real-world crashes, caught before running
Anchor 4

Generics, Callable, TypedDict

Stats = tuple[float, float, float]          # (min, mean, max)
per_station: dict[str, Stats] = {}          # the billion-row result

def apply(f: Callable[[float], float], x: float) -> float: ...

class Reading(TypedDict):                    # the shape of a dict
    station: str
    temperature: float
Back to earlier weeks: the billion-row stats, functions as objects, and JSON-like records. TypedDict catches key typos like r["temprature"].
Anchor 5

Protocol: duck typing, but checked

class Speaker(Protocol):
    def speak(self) -> str: ...

class Dog:               # no inheritance
    def speak(self) -> str:
        return "Woof"

def announce(s: Speaker): ...

announce(Dog())      # OK
announce(Rock())     # mypy error
  • "Anything with a speak() method counts"
  • No base class needed, so it works with code you did not write
Tooling

Three tools, three jobs

ToolCommandCatches
Type checker (mypy)mypy .wrong types, missing None handling
Linter (ruff)ruff check .unused imports and variables, likely mistakes
Formatter (ruff)ruff format .spacing and layout, so nobody argues about style
Fast, automatic, and run on every commit: that is what keeps large codebases manageable.
Side note: your git workflow

Run the checks on every push

# .github/workflows/checks.yml
on: [push, pull_request]
jobs:
  lint-and-types:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
      - run: pip install ruff mypy
      - run: ruff check .
      - run: mypy .
GitHub runs this on every pull request (week 3's branch, push, pull request flow). We build the full version in week 10.
Industry relevance

Why big codebases use this

  • Catches bugs early: before running, before review, before users
  • Better editors: autocomplete and safer refactoring
  • Easier collaboration: signatures document themselves
  • Adopt gradually: add hints file by file, tighten mypy over time
