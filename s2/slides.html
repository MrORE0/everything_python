Anchor 2

Generator Functions & yield

def count_up_to(n):
    i = 1
    while i <= n:
        yield i      # pause here
        i += 1       # resume here

gen = count_up_to(3)   # runs nothing!
next(gen)              # 1
next(gen)              # 2
  • Calling it only builds the generator
  • next() runs until the next yield
  • Local variables survive the pause
  • Falling off the end raises StopIteration

Anchor 4

Infinite Sequences

from itertools import islice

def fibonacci():
    a, b = 0, 1
    while True:          # never ends -- and that's fine
        yield a
        a, b = b, a + b

list(islice(fibonacci(), 10))   # you decide how much to take
Real uses: sensor feeds, log tails, event streams. list(fibonacci()) would run until memory dies.

Before you go write generators everywhere

Four ways they bite

  • One-shot: once consumed, it is empty
  • No indexing: gen[0] is a TypeError; use next() or islice
  • Closed resources: a with block can close the file before you read from it
  • Late binding: variables are looked up when consumed, not when created
Industry relevance

Where this shows up

  • Data pipelines (ETL, log processing)
  • Streaming systems (never-ending input)
  • Memory-efficient processing of big files
  • Under the hood of async, pytest fixtures, and web frameworks
